# 学びの扉 公式サイト

**学びの扉** の公式サイトです。

React 19 + TypeScript + Vite + Tailwind CSS（CDN）+ framer-motion 構成。

---

## [重要] 最重要：組織構造（3つの活動）

**「学びの扉」はひとつの団体名ではなく、3つの活動の総称です。**
3つは **資金・会計・運営をそれぞれ独立して** 行っており、
一方の活動が他方の債務や責任を負うものではありません。
そのため **サイト上でもページを分けて** 記載しています。

| ID | 活動 | 種別 | ページ | |---|---|---|---| | `app` | 学びの扉アプリ | 学習サービスの開発・運営（事業） | `/app` | | `community` | 学生学修コミュニティ「まなとび」 | 三重大学での探究活動 | `/community` | | `music` | 音楽活動「まなとび。」 | 楽曲制作・配信リリース | `/music` |

## [重要] 最重要：名称の表記ルール（句点「。」の有無）

**音楽活動のアーティスト名義は、句点まで含めて「まなとび。」です。**
句点のない「まなとび」は別の活動（学生学修コミュニティ）を指すため、
句点を付け忘れたり、逆に付け違えたりしないでください。

| 対象 | 正しい表記 | 英記 | |---|---|---| | 総称（組織全体） | 学びの扉 | Manabi-no-Tobira | | 学習サービスの事業 | 学びの扉アプリ | Manabi-no-Tobira App | | 三重大学の探究活動 | 学生学修コミュニティ「まなとび」（**句点なし**） | Manatobi Student Community | | 音楽活動 | 音楽活動「まなとび。」（**句点あり**） | **Manatobi.** |

> 総称（組織名）のみ「学びの扉」に改称しました。
> 個別の活動名である「まなとび」「まなとび。」は **改称していません**。

### 実装上のルール

- `content/site.ts` の `DIVISIONS` が3活動の唯一の定義元です。
- `ACTIVITIES` / `REPORTS` / `TIMELINE` / `TEAMS` は必ず
  `division: 'app' | 'community' | 'music'` を持ちます。
  **新しいデータを追加するときは必ず `division` を指定してください。**
- 3活動をまとめて「学びの扉という団体」と書かないでください。
  総称であること、会計が別であることが伝わる書き方にします。
- `components/ui/DivisionNotice.tsx` の
  `IndependenceNote` / `StructureNote` を使って、
  この分離を各ページで一貫して表示します。
  なお `division` は表示用のタグではなく、データの分類・
  活動別ページへの振り分けのために保持しています
  （画面に色付きタグとして出す `DivisionTag` は削除済みです）。
- 学習アプリの運営主体は **学びの扉アプリ** です。
  「学びの扉が開発・運営」ではなく「学びの扉アプリが開発・運営」と書きます。
- 利用規約・プライバシーポリシーの「当団体」は
  **学びの扉アプリのみ** を指します（他の2活動は当事者ではありません）。

## 最重要：個人情報の掲載方針

**大学の許可が必要なため、個人を特定できる情報は掲載しません。**

- [不可] 掲載しない：氏名、所属学部、顔写真、その他個人が特定できる情報
- [済] 掲載する：役割（担当領域）、人数規模など個人が特定されない範囲の情報

このため、旧 `MEMBERS`（個人名つき）は削除され、
役割のみを持つ **`TEAMS`** に置き換えられています。
`ORG.representative` も役職表記（`'学びの扉 運営代表'`）のみです。

**許可が取れるまで、この方針を変更しないでください。**

| 編集したいもの | 編集する定数 | |---|---| | **3つの活動の定義・独立性の注記** | **`DIVISIONS`** | | 総称としての名称・メール・URL 等 | `ORG` | | 教育への考え方（4項目） | `VALUES` | | 活動内容（取り組み一覧・要 `division`） | `ACTIVITIES` | | 教材ラインナップ | `MATERIAL_ITEMS` | | 運営体制（役割のみ・要 `division`） | `TEAMS` | | 活動報告（記事・要 `division`） | `REPORTS` | | 活動実績の数値 | `ACHIEVEMENTS` | | 活動のあゆみ（年表・要 `division`） | `TIMELINE` | | 音楽活動のリリース楽曲 | `MUSIC_RELEASES` | | よくあるご質問 | `FAQS` |

## Google AdSense の設定手順

1. `content/site.ts` の `TODO:` 項目をすべて実際の情報に差し替える
2. `/privacy`（プライバシーポリシー）と `/terms`（利用規約）の内容を確認
   - 広告配信・Cookie・アクセス解析の記載は既に整備済みです
3. AdSense に申請し、承認後 `index.html` の
   `===== Google AdSense =====` コメントブロックを解除
4. `ca-pub-XXXXXXXXXXXXXXXX` を自身のパブリッシャーIDに差し替え
5. **`public/ads.txt` を作成する**（下記参照）

### ads.txt について（承認後に対応する項目）

`ads.txt` は「この広告枠を売る権限を持つのは誰か」を宣言し、
広告枠のなりすまし販売を防ぐためのファイルです。

**[重要] 現時点ではこのファイルを置いていません。**
内容にパブリッシャーID（`pub-` から始まる16桁の数字）が必要で、
これは AdSense の審査に通ってアカウントが発行されるまで分かりません。
仮の値やダミーのIDを書いたファイルを置くと、
Google 側で「無効な ads.txt」として警告が出て逆効果になるため、
**IDが判明してから作成してください。**

審査通過後、`public/ads.txt` を新規作成し、以下の1行だけを記述します
（`pub-0000000000000000` を実際のIDに差し替えてください）。

```
google.com, pub-0000000000000000, DIRECT, f08c47fec0942fa0
```

`public/` に置いたファイルはビルド時にサイト直下へコピーされるため、
`https://manatobi.jp/ads.txt` で配信されます。
反映確認は AdSense 管理画面の「サイト」→「ads.txt の状況」から行えます。

### 審査に向けて整備済みの項目

- [済] 団体の実在性が伝わる情報（何の団体か / 誰が運営しているか / 何をしているか）
- [済] 独自性のある十分な分量のコンテンツ（16ページ・全ページ900文字以上）
- [済] プライバシーポリシー（Cookie・第三者配信広告・アクセス解析・オプトアウト手段を明記）
- [済] 利用規約（全13条）
- [済] 連絡が取れるお問い合わせ手段
- [済] 実際の活動実績と活動報告
- [済] 全ページからアクセスできる明確なナビゲーション
- [済] 構造化データ（`EducationalOrganization`）・OGP・canonical
- [済] `robots.txt` / `sitemap.xml`（16URL・ルーティング定義と一致）
- [済] 存在しないURLは 404 画面＋`noindex` を返す（ソフト404の回避）
- [済] `ORG.email` を実際に受信できるアドレスにする（`mntobira@gmail.com`）
- [済] `ORG.founded` を実際の開始年月にする（**2025年3月**）
      年月は **3か所** に散っています。片方だけ直すと食い違うため必ず全部直してください。
      1. `content/site.ts` の `ORG.founded`（`'2025年3月'`）… 画面表示
      2. `index.html` の JSON-LD `foundingDate`（`"2025-03"`）… 検索エンジン向け
      3. `content/site.ts` の `TIMELINE` 先頭項目の `date`（`'2025年3月'`）… 沿革の起点

### アイコンの作り方

ブラウザのタブに出るファビコンやスマホのホーム画面アイコンは、
**すべて公式ロゴ（`assets/brand/mntb-logo.png`）から自動生成**しています。
手作業で1枚ずつ作らないでください。

```bash
python3 scripts/make_icons.py      # ファビコン・アプリアイコン一式
python3 scripts/make_og_image.py   # OGP画像（SNS共有時のカード）
```

ロゴを差し替えたいときは次の2ファイルを更新してから、上のコマンドを実行します。

| ファイル | 用途 |
| --- | --- |
| `assets/brand/mntb-logo.png` | アイコン・OGP画像の生成元（できるだけ高解像度で） |
| `public/images/logo.png` | ヘッダーに表示するロゴ（`components/Logo.tsx`） |

#### [重要] 比率を絶対に変えないでください

ロゴは横長（約 3.22:1）ですが、アイコンの枠は正方形です。
枠に合わせて**縦か横だけを伸縮させるとロゴが歪みます。**

そのため生成スクリプトは「レターボックス方式」を使っています。

1. 縦横に**同じ倍率**をかけて縮小する（比率が変わらない）
2. 余った上下の領域を背景色（白）で埋める
3. ロゴを枠の中央に置く

つまり「余白を足して」正方形に収めており、「潰して」収めてはいません。
`make_icons.py` は生成後に全サイズの比率を自動検証し、
歪みがあればエラーで停止します。

なお、小さいアイコンでは比率の数値がわずかにずれます。
これは画像の高さを整数ピクセルに丸めるしかないためで、不具合ではありません
（例: 16px アイコンではロゴ高さが 4.8px → 5px に丸まります）。
検証の許容値は「高さ ±0.5px 分」に設定してあり、
本当の歪み（片方だけ伸縮した場合）だけを検出します。

#### [重要] `favicon.svg` は置かないでください

モダンブラウザは `favicon.svg` を `favicon.ico` **より優先**します。
以前この場所に旧デザイン（扉のイラスト）の SVG が残っていたため、
`.ico` をいくら差し替えてもタブに旧ロゴが出続ける状態になっていました。
現在は削除済みです。SVG を復活させる場合は、
必ず現行ロゴに合わせて作り直してから置いてください。

#### [重要] `favicon.ico` を手作業で作るときの落とし穴

Pillow の `img.save('x.ico', sizes=[...])` は、
**元画像より大きいサイズを黙って切り捨てます**（エラーが出ません）。
16px の画像から複数サイズを指定しても、中身は 16×16 だけになります。
必ず**一番大きいサイズ（256px）を先に作ってから** `sizes=[...]` を渡してください。
`make_icons.py` はこの順序を守り、生成後に収録サイズを検証しています。

#### maskable アイコンについて

`icon-maskable-512.png` だけロゴが小さく見えますが、これは意図的です。
Android はホーム画面のアイコンを円形に切り抜くため、
内側 約80% の「セーフゾーン」にロゴを収めないと端が切れてしまいます。

### ルーティングについて

`react-router` は使用せず、History API による軽量ルーティングを実装しています
（`App.tsx` の `PATHS`）。ブラウザの戻る/進む、URL の直接共有に対応します。

静的ホスティングでサブパスを直接開けるようにするため、
`public/_redirects`（Netlify / Cloudflare Pages）と
`public/404.html`（GitHub Pages 等）を同梱しています。
